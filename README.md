# Работы по курсам

Это ваш личный приватный репозиторий. Его видите только вы и преподаватель.
Работы по всем предметам лежат здесь, каждый предмет — в своей папке.

## Курсы

| Папка | Курс |
|---|---|
| [`ooad/`](ooad/) | Объектно-ориентированный анализ и проектирование |
| [`parallel-programming/`](parallel-programming/) | Технологии параллельного программирования |

Внутри папки курса — по папке на каждую работу и `README.md` с правилами
конкретного предмета.

```
ooad/
├── README.md
├── lab-01/
│   ├── README.md      что сделано, как запускать
│   └── src/           исходники
└── lab-02/
```

## Как сдавать работу

1. Создайте ветку от `main`. Называйте её по курсу и номеру работы:
   ```bash
   git switch -c ooad/lab-01
   ```
2. Работайте в папке своего курса, коммитьте небольшими осмысленными кусками:
   ```bash
   git add ooad/lab-01
   git commit -m "ooad/lab-01: диаграмма классов и описание сценариев"
   git push -u origin ooad/lab-01
   ```
3. Откройте Pull Request `ooad/lab-01 → main` (ссылка появится после `push`).
   В теле PR заполните шаблон — обязательно укажите курс и номер работы.
4. Преподаватель оставит замечания прямо по строкам. Правьте в той же ветке —
   PR обновится сам, новый создавать не нужно.
5. Когда работа принята, PR мержится в `main`. Работа засчитана.

> Сдача идёт через Pull Request, а не коммитом в `main`, — так замечания
> привязываются к конкретным строкам, а история сдач остаётся видимой.

## Правила

- Один PR — одна работа по одному курсу. Не смешивайте предметы в одной ветке.
- Не коммитьте бинарники, архивы, `node_modules/`, `bin/`, `obj/`.
- Не коммитьте пароли, токены и ключи. Если случайно закоммитили — сразу
  сообщите преподавателю: удалить из истории сложнее, чем кажется.
- Один коммит = одна законченная мысль. `fix`, `123`, `asdf` — не сообщения коммита.
- Репозиторий приватный, но не делайте его публичным и не приглашайте туда
  других: чужая работа в вашем репозитории считается списыванием у обоих.
